Data Flow for our App
Here is the straight-to-the-point, zero-fluff data flow for your Python/Mistral stack.

By keeping a strict separation of concerns between your UI and your logic—a core software engineering fundamental—you and your teammate can build this in parallel without blocking each other.

### **The File Structure**

* `overlay_ui.py` (Handles the screen, PyQt6 transparent window, and user input)
* `ai_brain.py` (Handles OpenCV, bounding box math, and Mistral API calls)

---

### **The Runtime Loop (Step-by-Step)**

**1. The Trigger (`overlay_ui.py`)**

* The user types a request (e.g., "How do I add a blur?") in your chat widget and hits Enter.
* The PyQt6 app instantly uses `mss` to take a full-screen screenshot and saves it as `raw_screen.png`.
* The app passes the image path and the user's text to a background thread to prevent the UI from freezing.

**2. The Vision Engine (`ai_brain.py`)**

* The script receives `raw_screen.png` and runs OpenCV edge detection (`cv2.findContours`).
* It filters out the noise (shapes too big or too small).
* It generates a dictionary mapping an ID to coordinates: `{"1": [x, y, w, h], "2": [x, y, w, h]}`.
* It draws a numbered red box over every detected element and saves this new image as `marked_screen.png`.

**3. The Brain Call (Mistral API)**

* Your script sends `marked_screen.png` and the user's text to the Mistral VLM API.
* **The System Prompt:** *"You are a UI navigation assistant. Look at the numbered boxes on the provided image. The user wants to: [USER TEXT]. Which box number must they click to achieve this? You must reply with ONLY the integer of the box."*

**4. The Translation (`ai_brain.py`)**

* Mistral's API returns a single string, e.g., `"14"`.
* Your script converts it to an integer, looks up ID `14` in your OpenCV dictionary, and extracts the exact `[x, y, width, height]` coordinates.
* It returns those coordinates back to the UI thread.

**5. The Reveal (`overlay_ui.py`)**

* The PyQt6 app receives the coordinates.
* It triggers the `paintEvent` to draw a glowing, high-contrast bounding box exactly over those coordinates on your transparent window.
* The user sees the highlight and clicks the real app underneath.

---

That is the entire loop. No heavy local AI models, no complicated web sockets, just clean data passing between two files.

# :page_facing_up: Single Source of Truth (SSOT): Project "ClearPath"

## 1. The Narrative & Scope

* **The Problem:** The modern digital world strips the elderly of their independence. Simple roadblocks—like forgetting a password—force them to rely constantly on family members or caregivers to access basic services like banking. This creates a painful cycle: the elderly feel helpless and lose their autonomy, while caregivers are burdened with the repetitive, frustrating task of acting as permanent tech support.
* **The Solution:** A localized, contextual AI overlay that acts as a patient digital guide. It gives autonomy back to the user by "seeing" the screen and physically drawing a glowing box around the exact next step, teaching them how to navigate the digital world themselves and eliminating the need to call their kids for help.
* **Demo Target:** A custom-built, local HTML/CSS mock "Bank Login" page. This guarantees a controlled environment where the "Forgot Password" and "Submit" triggers are styled as clean, geometric shapes that our vision engine can detect with 100% reliability and zero latency.

## 2. The Tech Stack

* **Core Language:** Python 3.10+
* **Frontend (The Glass):** `PyQt6` (Creates the transparent, frameless, always-on-top overlay and chat widget).
* **Screen Capture:** `mss` (Lightning-fast cross-platform screenshots).
* **Vision Engine:** `OpenCV` (`cv2`). Tuned specifically for clean web UI edge-detection (high accuracy, zero latency). **No OCR required** due to the controlled mock environment.
* **Reasoning Engine:** Mistral API (Pixtral VLM) for semantic understanding of the marked-up screen and empathetic response generation.

## 3. The Architecture & Interaction Flow

This system is strictly decoupled into a "Client" (UI) and a "Server" (AI Logic) to prevent merge conflicts and allow parallel development.

1. **Invocation:** User types "I can't remember my password" into the floating PyQt6 chat widget.
2. **Capture:** UI thread takes a screenshot (`raw.png`) and passes it to the AI worker thread.
3. **Vision Pass:** OpenCV converts `raw.png` to grayscale, runs edge detection, and draws a numbered box over every button-like shape. Saves as `marked.png`.
4. **Reasoning Pass:** `marked.png` and the user's prompt are sent to Mistral. Mistral's System Prompt forces it to act as a patient guide and reply with *only* the correct box ID number.
5. **Resolution:** The AI thread maps the ID back to the OpenCV coordinates and returns them to the UI thread. The PyQt6 app draws a glowing neon box over the target element.

## 4. The Internal API Contract

The UI (`overlay_ui.py`) and the Brain (`ai_brain.py`) will communicate using this exact data structure.
